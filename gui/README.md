# Audio Share Server GUI

Tauri v2 shell (Rust) + Svelte 5/Vite frontend. The GUI is a tray-first single
window that starts and stops an in-process Audio Share Core `Server`.

## Layout

```
gui/
  package.json, vite.config.ts, svelte.config.js, tsconfig.json
  index.html
  dist/                    # generated by `npm run build`; ignored by git
  src/                     # Svelte 5 + TypeScript frontend
    locales/en-US.json     # single source of truth for UI strings (also embedded in Rust)
  src-tauri/               # workspace member `audio-share-server-gui`
    src/lib.rs             # testable controller/model/options/strings
    src/main.rs            # Tauri window, tray, commands, events
    tauri.conf.json
    capabilities/default.json
    icons/                 # generated from server-mfc/.../AudioShareServer.ico with `tauri icon`
```

## Build and run

Prerequisites: Node 22+, Rust 1.90+, and the Tauri Linux build/runtime
dependencies listed in `docs/server-rewrite/` exploration notes (`tauri.md`).

```bash
cd gui
npm ci
npm run check            # svelte-check
npm run build            # writes the ignored gui/dist/
npx tauri build --debug --no-bundle
```

With the Cargo workspace, the binary lands at `<repo>/target/debug/AudioShareServer`
(`target/release/AudioShareServer` for a release build). Use
`npx tauri build --no-bundle` for the shippable Windows portable exe. On Linux,
`npx tauri build --bundles deb,appimage` reads `src-tauri/tauri.linux.conf.json`
and writes the bundles under `<repo>/target/release/bundle/`; see
[`docs/server-rewrite/build-linux.md`](../docs/server-rewrite/build-linux.md).

`tauri build` runs `npm run build` first and enables `tauri/custom-protocol`,
which embeds `frontendDist` (`../dist`) into the binary.

### Dev-URL binary vs embedded assets

A bare `cargo build -p audio-share-server-gui` does **not** embed the frontend:
Tauri treats it as a dev build and the window loads `devUrl`
(`http://localhost:1420`), so it needs `npm run dev` running. For a bare-Cargo
production build, build the frontend first and opt in explicitly:

```bash
cd gui && npm run build
cargo build -p audio-share-server-gui --features audio-share-server-gui/custom-protocol
```

`gui/dist/` is generated by `npm run build` and is not tracked. A bare
`cargo build`/`cargo check` needs no `dist/`: without `custom-protocol` the
binary loads `devUrl`, and `tauri build` runs `beforeBuildCommand`
(`npm run build`) before embedding `frontendDist`. Nothing under `gui/dist/`
appears in `git status` after either command.

## Debug flags

- `--fake-capture` — deterministic synthetic capture instead of PipeWire/WASAPI.
- `--hide` (also `-hide`, `/hide`) — start with the window hidden (autostart path).
- `--smoke-test` — log window title/size after 4 s and exit 0. Example:

```bash
xvfb-run -a -s "-screen 0 1280x800x24" dbus-run-session -- bash -c '
  export WEBKIT_DISABLE_COMPOSITING_MODE=1 WEBKIT_DISABLE_DMABUF_RENDERER=1
  export LIBGL_ALWAYS_SOFTWARE=1 GDK_BACKEND=x11
  ./target/debug/AudioShareServer --smoke-test
'
```

## Behaviour (tickets 08-10)

- Window 420x640, title "Audio Share Server". `--hide` (also `-hide`, `/hide`)
  starts hidden with the tray present. Close follows `WhenClose`: 0 stops the
  core and exits, 1 hides to the tray. Tray Exit and the Settings Quit button
  always stop the core and quit.
- Launch follows `WhenAppStart`: 0 nothing, 1 start the server, 2 start when
  `[App] Running` was true. It runs asynchronously after setup.
- Autostart is written directly (not via `auto-launch`) so paths are quoted:
  Windows HKCU `Software\Microsoft\Windows\CurrentVersion\Run` value
  `AudioShareServer` = `"<exe>" /hide`; Linux
  `$XDG_CONFIG_HOME/autostart/AudioShareServer.desktop` (default
  `~/.config`) with `Exec="<exe>" --hide` and `TryExec=<exe>`, using
  `$APPIMAGE` when set. `[App Settings] AutoRun` is reconciled at every start.
- `en-US` and `zh-CN` resources live in `src/locales/`; both are embedded in
  Rust for tray/notification text. `[App] language=default` follows the system
  locale (`zh*` -> `zh-CN`, else `en-US`). The language is applied before the
  shell mounts; changing it persists and shows a restart hint.
- The About modal shows product, version, homepage (opens the browser),
  Apache-2.0, and copyright.
- Update checks GET GitHub `releases/latest` with a User-Agent and 10 s
  timeout, compare the tag with the v0.3.4 algorithm, show an in-app banner plus
  a native notification, and open `html_url` from the banner. Automatic checks
  run at startup and every 3 hours while `AutoUpdate`; manual checks report
  Up To Date or a readable error. `AUDIO_SHARE_UPDATE_URL` overrides the
  endpoint for replay-based testing only.
- Tray: Show / Start / Stop / separator / Exit; Start and Stop are enabled per
  server state. Windows left-click toggles the window. Linux only delivers the
  right-click menu (Tauri limitation).
- Start/Stop run asynchronously through `ServerController`; the status event
  `server:state-changed` carries `{ state, address, lastError }`.
- Settings load from and save to `config.ini` (resolution order in
  `docs/server-rewrite/`); application settings stay editable while the server
  runs. Defaults: selected default host, port 65530, endpoint `default`,
  encoding `default`, `WhenClose=1`.

## Tests

```bash
cargo test -p audio-share-server-gui          # controller, autostart, i18n, update
cargo clippy -p audio-share-server-gui --all-targets -- -D warnings
cargo check --target x86_64-pc-windows-msvc -p audio-share-server-gui
(cd gui && npm run check && npm run build)
```

Under Xvfb, run inside `dbus-run-session` (the single-instance, tray, and
accessibility services need a session bus) and set
`WEBKIT_DISABLE_COMPOSITING_MODE=1`, `WEBKIT_DISABLE_DMABUF_RENDERER=1`,
`LIBGL_ALWAYS_SOFTWARE=1`, `GDK_BACKEND=x11`.
