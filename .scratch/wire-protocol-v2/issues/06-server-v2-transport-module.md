# 06: Server v2 transport module — production skeleton

**What to build:** 在生产 Server Core 中落地 v2 传输模块骨架：quinn endpoint、Server 身份钥、连接生命周期、资源限额、golden-vector 回放工装。这是 Tracer-Bullet 第 3 步（最小认证 v2 控制通道）的服务器侧地基；本工单交付到「能接受连接、拒绝不合规者」，认证流程在 07。

**Blocked by:** 02, 05

**Status:** resolved

**Type:** task

## Requirements

- 在 `crates/audio-share-core` 新增独立 v2 模块（建议 `src/v2/`，与 v1 `src/protocol/` 平行；Implementation Boundary：v2 handshake/control/sessions 独立成模块，不复用 v1 Protobuf 做内部 API）。若 crate 边界更清晰可建 `crates/v2-transport`，二选一并记录理由。
- quinn 0.11 endpoint：ALPN `audio-share/v2`（major 不匹配在应用数据前显式失败）、rustls TLS 1.3（rustls 默认套件 + X25519，D7）、0-RTT 永久禁用、默认监听 `65531/udp`（D1；与 v1 的 65530 并行、独立可禁用）。
- Server 身份钥（pairing.md：Ed25519，PR-1）：生成 + 持久化（0600/0700、原子写 + 1 备份、损坏 fail-closed 不自动再生、POSIX 宽松权限拒绝启用 v2 + `--allow-loose-key-permissions` 覆盖、Windows 仅警告）；SPKI SHA-256 指纹在启动日志输出。
- 资源限额落地（threat-model TM-1..8 与 spec §10）：并发握手、总 session 数（32）、每 Client 1 session（新替旧）、pre-auth 响应 ≤128 B、错误 ≤512 B/detail ≤256 B、控制消息 64 KiB 上限（超限 401+Close，先于任何分配）。非等待发送 + 应用层有界队列。
- QUIC close 携带 §6 错误注册表的应用错误码；连接生命周期状态经域 API 暴露最小可见性（as-cmd/GUI 观察共同 v1/v2 生命周期状态，不解析线缆字节 —— 本工单只做管道，不做 UI）。
- **Golden-vector 回放工装**：Rust 侧 encoder 对 `fixtures/wire-protocol-v2/` 的 control happy/error 案例（34+3 个）做双向字节对拍（复用/扩展 ticket 05 的回放契约）；实现不得有自己的私有编码。
- 规范红线：v1 模块、`docs/protocol.md`、v1 fixtures 一律不动；v1 在每个提交点保持可构建可发布。

## Definition of done

- 新增模块 `cargo test` 绿：身份钥生命周期测试（生成/重载/损坏/权限）、限额测试、close-错误码测试、非等待队列测试。
- Vector 回放：全部 control 案例（error-registry 25 + negative 5 + happy 6）字节一致。
- 回归：`protocol-harness replay` 全绿；v1 集成测试全绿；现有 `as-cmd`/GUI 行为不变（v2 关闭时零行为差异）。
- `as-cmd --v2-port=65531`（或等价配置）能起停 v2 监听并有日志；默认随 Server 启用。

**Module choice: `crates/v2-transport` (separate crate), not `audio-share-core/src/v2/`.** Rationale: (1) the v1 crate's dependency tree stays frozen-v1-shaped — quinn/rustls/ring/rcgen/p256 add roughly 5 MiB of binary that nothing in `audio-share-core`, the GUI, or `protocol-harness` needs until they opt into v2; (2) the ticket's Implementation Boundary ("v2 handshake/control/sessions independent, never reusing v1 Protobuf internally") is enforced by the compiler across a crate edge instead of by convention inside one module tree; (3) ticket 07 (auth/session state machine) and later tickets can consume the crate via the domain API without touching v1 build graph. `audio-share-core` remains untouched by this ticket (red line held: `git diff 8090f71..HEAD -- crates/audio-share-core docs/protocol.md fixtures/protocol` is empty).

**Test counts** (`cargo test --workspace`): 353 passed / 0 failed across 30 binaries; v2-specific additions: `v2-transport` lib 60 tests (schema/framing/codes/identity/limits/send_queue/session/transport) + `golden_vectors` integration 3 tests + `as-cmd` 4 live-process tests (`tests/v2_server.rs`) + 1 help-parity assertion extended; baseline before this ticket was 286.

**Golden-vector replay** (`crates/v2-transport/src/vectors.rs` behind the `test-support` feature, self dev-dependency so it runs under plain `cargo test` without CI feature flags): all 41 control-plane cases (error-registry 26 + happy-path 6 + negative-space 6 + limits 3) replay byte-exactly in both directions per ticket 05's contract — encode-from-`decoded` == `frame_hex`, `body_hex` decodes to the built frame, raw-stream violations reject on the length prefix before any allocation, transport-close codes checked against the §6 registry, size bounds (128 B pre-auth / 320 B PairingResponse) asserted, and signature-carrying cases verified against the fixed test client key (never reproduced), with the two corrupted cases (203, 201-proof-invalid) recording `signature-invalid-confirmed` — the verifier provably rejects them. Unknown-field steps replay decode-only (prost cannot encode unknown fields; the proto3 evolution rule is the spec's).

The harness now reads `decoded` Status flags literally (no private encoding); when ticket 07 builds the real sender on `Status::registry()`, the maintainer must rule whether the declined-201 vector gains the flag (and both replay harnesses flip together) or the vector's literal form is authoritative.

**Key decisions:**
- Endpoint per ADR-0004/D1/D3/D7: quinn 0.11 + rustls ring TLS 1.3, ALPN exactly `audio-share/v2` (mismatch fails in the handshake, before application data — loopback-tested with a wrong-ALPN client), 0-RTT permanently off (`max_early_data_size = 0`), 30 s idle timeout + 10 s keep-alive, default bind 65531/udp parallel to v1's 65530.
- Identity (pairing.md §10.2/§10.3/PR-1): `<data dir>/identity/server-identity.pem`, 0600 file / 0700 dir, atomic write + one `.bak` generation, corruption fail-closed and never auto-regenerated; POSIX loose-permission refusal disables v2 while v1/capture continue, `--allow-loose-key-permissions` overrides (logged as discouraged); Windows compiles to warn-only per §12. Freshly created identity dirs are tightened to 0700 explicitly (create_dir_all honors umask); pre-existing loose dirs fail closed — never silently repaired.
- Limits (TM-1..8/§10) as a pure domain API: 16 concurrent handshakes, 32 sessions (session bound outranks handshake bound; both reject with 301), 5 auth failures per connection then Close(203), 20 auth failures per source per sliding 60 s then 302, pre-auth framed responses ≤ 128 B, PairingResponse exception ≤ 320 B, post-auth errors ≤ 512 B total / detail ≤ 256 B, 64 KiB control-frame cap enforced in `check_length_prefix`/`FrameReader::push` before any allocation (65 536 itself accepted), non-waiting `SendQueue` with drop-newest accounting.
- QUIC close codes: every termination carries its §6 registry code via `classify_close` (application-close code → registry, else classified 601 locally); administrative stop closes with 503; capacity refusals happen pre-handshake (`Incoming::refuse`, transport-level CONNECTION_REFUSED) with the 301 outcome reflected in the lifecycle.
- Lifecycle visibility: `ConnectionLifecycle` (Connecting…Closed states incl. the ticket-07 states) + `Termination{ServerClosed/ClientClosed/Lost}` — the domain API as-cmd/GUI observe; no UI in this ticket.
- as-cmd: `--v2-port` (default 65531, `0` disables) + `--allow-loose-key-permissions`; identity fingerprint logged at startup; accept loop owns the capacity guards and logs every connection outcome; stop path closes the endpoint (503) before the v1 stop. `--v2-port=0` produces zero behavior difference (no v2 logs, no identity files on disk, v1-only run identical to the pre-v2 binary — live-tested). Default is enabled with the Server, live-tested on 65531.
