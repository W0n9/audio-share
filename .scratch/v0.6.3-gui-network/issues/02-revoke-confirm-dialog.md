## Agent Brief

**Category:** bug
**Summary:** 原生 `window.confirm` 在窄的 Windows WebView2 窗口里被截断，提示与按钮显示不全。

**Current behavior:**
- 配对对话框中的“撤销”和“删除”动作调用 `window.confirm(...)`，参数来自本地化文案。
- 在 Windows 的 380–420px 宽窗口里，原生脚本对话框显示不全，用户无法完整阅读提示与按钮。

**Desired behavior:**
- 撤销与删除都改为应用内模态框，复用现有配对对话框的遮罩、表面色、圆角与排版。
- 模态框显示完整本地化文案，提供明确的“确认/取消”两个动作；破坏性动作使用语义色主按钮。
- Escape 或取消关闭模态框且不执行动作；确认才执行原动作。
- 模态框在 380×560 下完整可见，文本换行，按钮无需横向滚动。
- 打开时焦点进入模态框，关闭后焦点回到触发按钮；背景内容不可交互。
- GUI 中不再有原生 `confirm`/`alert` 调用。

**Key interfaces:**
- 配对对话框视图的 revoke / delete 处理函数。
- 现有 i18n 键 `pairing.confirmRevoke`、`pairing.confirmDelete` 的文案可复用或拆分。
- 可复用的模态框/遮罩样式与焦点管理；不得复制出第二套视觉语言。
- 后端 `clients_revoke` / `clients_delete` 命令与参数不变。

**Acceptance criteria:**
- [ ] 撤销与删除不再调用 `window.confirm`。
- [ ] 两个流程都显示应用内模态框，含本地化提示与两个动作。
- [ ] Escape/取消关闭且不执行；确认执行原动作。
- [ ] 在 380×560 下模态框完整可见，文案换行，按钮可达。
- [ ] 焦点进入/归还正确，背景不可交互。
- [ ] `gui/src` 中不存在其他 `confirm`/`alert` 调用。
- [ ] `svelte-check` 与生产构建通过。
- [ ] Windows 真机视觉复验并记录证据；无法复验时记 `NOT RUN`。

**Out of scope:**
- 改变撤销/删除的业务语义或后端行为。
- 增加撤销（undo）能力或延迟删除。
- 全局主题/设计系统改造。
