# 04: 二维码地址提示使用配置的 Host

> *This was generated by AI during triage.*

**What to build:** 二维码配对 payload 的 `addr` 提示改为使用用户在 Network configuration 里配置的 Host；IPv6 字面量按 `[addr]:port` 编码。v2 仍绑定双栈通配地址，连接行为不变。

**Blocked by:** 无

**Category:** bug
**Status:** ready-for-human

## Agent Brief

**Category:** bug
**Summary:** GUI 启动 v2 时固定 `addr_hint: None`，运行时回落到首个 IPv4；用户填写的 IPv6 Host 被忽略。

**Current behavior:**
- GUI 的 v2 starter 启动共享 runtime 时传入 `bind_host: "::"` 与 `addr_hint: None`，启动输入里没有 Host 字段。
- runtime 在 `addr_hint` 为 `None` 时取本机默认非 loopback IPv4，拼成 `host:port`。
- 因此即使用户把 Host 填成 IPv6 地址，二维码里的 `addr` 仍是 IPv4。
- `settings.host` 目前只作用于 v1 的绑定，不参与 v2。

**Desired behavior:**
- Host 是具体地址或主机名时，二维码 `addr` 使用该 Host 与 **v2 实际监听端口**。
- Host 是 IPv6 字面量时编码为 `[<ipv6>]:<port>`；配对 payload 校验器与 Android 客户端都已支持方括号形式。
- Host 为空、`0.0.0.0` 或 `::` 时保持现状：回落到本机默认非 loopback IPv4。
- Host 含 `%scope`（如 `fe80::1%eth0`）时不得生成非法 payload；行为必须明确（给出提示并回落，或报错），并有测试。
- v2 仍绑定 `::` 双栈；不改变客户端连接、配对或会话行为。
- v1 的 Host/端口语义不变。

**Key interfaces:**
- GUI 的 v2 启动输入（`V2StartInputs`）：需要携带当前 `settings.host`。
- v2 starter 构造 `RuntimeConfig` 时：设置 `addr_hint`，保持 `bind_host` 为双栈通配。
- `RuntimeConfig.addr_hint` 的语义保持“QR 中广告的 `host:port`；`None` 时推导默认地址”。
- `CorePairingAdmin` 的地址提示与二维码生成路径不变。
- 配对 payload 的 `addr` 校验已接受方括号 IPv6；生成侧需与之匹配。

**Acceptance criteria:**
- [ ] Host 为具体 IPv6 时，QR `addr` 为 `[<ipv6>]:<v2 实际端口>`。
- [ ] Host 为具体 IPv4 或主机名时，QR `addr` 为 `<host>:<v2 实际端口>`。
- [ ] Host 为空或通配地址时，QR `addr` 与当前默认行为一致（首个非 loopback IPv4）。
- [ ] Host 含 `%scope` 时不产生非法 payload；行为有测试覆盖。
- [ ] v2 仍绑定双栈通配；现有客户端连接方式不变。
- [ ] 生成的 `addr` 能被 `parse_qr_uri` 接受；Android 地址解析器接受该形式。
- [ ] Rust 测试覆盖 IPv4、IPv6、主机名、通配、带 scope 五类输入。
- [ ] v1 绑定/端口与采集行为不变。
- [ ] 在 Windows 真机走通一次 QR 配对并记录证据；无法复验时记 `NOT RUN`。

**Out of scope:**
- 让 Host 同时控制 v2 的绑定地址（维护者已决定只改广告地址）。
- 多网卡/多地址广告、自动探测手机可达的地址。
- 修改配对 URI scheme 或 payload 版本。
- 运行中热切换 Host；仍沿用“运行中设置锁定、重启生效”。
