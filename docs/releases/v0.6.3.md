# Audio Share 0.6.3

0.6.3 is a Server GUI and Android Client maintenance release on top of 0.6.2. Wire Protocol v2, the audio path, and the supported client count are unchanged.

## Server GUI and network configuration

- **Pairing:** the **Accept** / **Reject** buttons for a pending request are now visible without scrolling, so a pairing approval no longer hides behind a scroll at small window sizes.
- **Confirmations:** **Revoke** and **Delete** now use an in-app confirmation dialog instead of the native browser prompt, which was clipped in narrow Windows windows. The dialog is fully visible at 380×560, supports Escape / Cancel, and returns focus after the action.
- **Host address:** the field is now a dropdown listing detected addresses (IPv4 plus usable global / ULA IPv6) with an explicit **Custom…** option for a hostname or address. Link-local, loopback, multicast and Teredo addresses are excluded. A failed save now rolls back to the last saved value instead of leaving the GUI and the stored configuration out of sync.
- **Pairing QR code:** the advertised address now uses the configured Host. IPv6 addresses are encoded as `[addr]:port`. The v2 server still binds to a dual-stack wildcard address; this change only affects the address advertised in the QR code.
- Host values with a `%scope` suffix are rejected on save with a localized error, since they cannot be advertised in the QR code.

## Android Client

- The v2 Android app now has a launcher icon, matching the v1 app's icon in design and proportions. The icon also supports Android 13 themed icons.

## Install and upgrade

Installs built from 0.6.2 can be overwritten in place: the Android signing key and application ID (`dev.audioshare.v2`) are unchanged, so saved pairings are preserved. Each asset has a `.sha256` sidecar; verify before opening it:

```sh
sha256sum -c audio-share-client-v2-0.6.3-arm64-v8a.apk.sha256
```

| Platform | Asset |
|---|---|
| Android (arm64 phones) | `audio-share-client-v2-0.6.3-arm64-v8a.apk` |
| Android (x86_64) | `audio-share-client-v2-0.6.3-x86_64.apk` |
| Windows GUI | `AudioShareServer.exe` |
| Windows headless | `audio-share-server-cmd-windows.zip` |
| Linux GUI (deb) | `AudioShareServer_0.6.3_amd64.deb` |
| Linux GUI (AppImage) | `AudioShareServer_0.6.3_amd64.AppImage` |
| Linux headless | `audio-share-server-cmd-linux.tar.gz` |

Upgrading from 0.6.0/0.6.1/0.6.2 keeps the existing pairing records and device keys. The v2 Server listens on UDP 65531 (QUIC); allow it through the firewall. See the [README](../../README.md) for pairing steps, `as-cmd` flags, and build instructions.

## Compatibility and known limitations

- One v2 Client per Server remains the supported configuration; concurrent phones and multi-client isolation are outside this release.
- When two or more pending pairing requests and a live device are present at the same time, a live pairing code can appear below the fold; the pending-request buttons remain visible.
- The v2 APK installs alongside the existing v1 Android app. The v1 app is unencrypted and unauthenticated and should only be used on a trusted network; a failed v2 connection never falls back to v1 or plaintext.
- Verify downloads against their SHA-256 checksums.

## Validation limits

Automated verification passed on the source: Rust `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` (676 tests), GUI `svelte-check` and Vite production build, and Android JVM tests (332 tests). Real-device reports from the maintainer cover the 0.6.3 GUI fixes and the Android launcher icon on the 0.6.2-versioned integration artifacts; the final 0.6.3-versioned release artifacts have not yet been re-tested on a real device and are `NOT RUN` here. The acoustic latency baseline, 60-minute soak, network impairment testing, and listening A/B remain waived or not run; this release does not claim p95/p99 audible-latency targets.
