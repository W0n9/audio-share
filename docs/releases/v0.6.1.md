# Audio Share 0.6.1

This release follows the published 0.6.0 build. It keeps the same Wire
Protocol v2 single-Client PCM capability and validation boundary, and fixes the
user-facing wording and attribution that were still carried over from the beta
build:

- The v2 Android Client's About page no longer labels the app as a beta and no
  longer claims that jitter buffering, loss concealment, and clock-drift
  correction are absent. Those features are part of this release.
- The Server GUI's About block and the v2 Android Client's About page now credit
  **© 2022-2026 Audio Share contributors** under Apache-2.0, instead of the
  upstream v1 copyright line.
- The GUI homepage, update check, `as-cmd --version`, and the Linux package
  homepage now point at the repository that publishes these builds:
  `https://github.com/W0n9/audio-share`. The v1 / F-Droid links are unchanged.

The Android signing key is unchanged, so installs built from 0.6.0 can be
overwritten in place. Older v2 beta installs may still hit the stale-credential
error 205 and need the uninstall/re-pair path described below.

## Downloads

Each asset has a `.sha256` sidecar in `sha256sum` format. Verify a download
before opening it:

```sh
sha256sum -c audio-share-client-v2-0.6.1-arm64-v8a.apk.sha256
```

| Platform | Asset |
|---|---|
| Android (arm64 phones) | `audio-share-client-v2-0.6.1-arm64-v8a.apk` |
| Android (x86_64) | `audio-share-client-v2-0.6.1-x86_64.apk` |
| Windows GUI | `AudioShareServer.exe` |
| Windows headless | `audio-share-server-cmd-windows.zip` |
| Linux GUI (deb) | `AudioShareServer_0.6.1_amd64.deb` |
| Linux GUI (AppImage) | `AudioShareServer_0.6.1_amd64.AppImage` |
| Linux headless | `audio-share-server-cmd-linux.tar.gz` |

The v2 Server listens on UDP port 65531 (QUIC); allow it through the firewall.
Windows GUI requires the WebView2 Runtime; Linux GUI requires WebKitGTK 4.1,
GTK 3, the StatusNotifier appindicator, and a running PipeWire session with a
session manager. See the [README](../../README.md) for pairing, `as-cmd` flags,
and build instructions.

## Compatibility and upgrade

- One v2 Client per Server is supported; concurrent phones and multi-client
  isolation are outside this release.
- The v2 APK (`dev.audioshare.v2`) installs alongside the existing v1 Android
  app. The v1 APK and its F-Droid listing are not replaced. **Use v1 only on a
  trusted network:** it is unencrypted and unauthenticated. A failed v2
  connection never automatically falls back to v1 or plaintext.
- If an older v2 beta leaves stale credentials (error 205), uninstall the old
  v2 app, install the new APK, and pair again. Uninstalling removes the app's
  saved pairings.
- Verify downloads against their accompanying SHA-256 checksums.

## Validation limits

The 0.6.0 release artifacts were verified on real Android hardware (install and
playback) and on Windows (Server packages run). Those results cover 0.6.0
builds, not the 0.6.1 artifacts: 0.6.1 changes only text and metadata, and its
own build still needs the same install, playback, and Server run before
publication. The upgrade path from older v2 beta builds is waived; uninstall the
old v2 app before installing this release.

The acoustic latency baseline and the 60-minute single-client run were waived;
this release does **not** claim the p95/p99 audible-latency targets. Real-network
impairment testing, device clock-drift injection, and listening A/B for the
drift-control change were not run. The impairment matrix was exercised on host
only. Multi-client and full migration/rollback acceptance are outside this
release.
