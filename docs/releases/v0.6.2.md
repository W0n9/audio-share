# Audio Share 0.6.2

0.6.2 follows the published 0.6.0 build and carries the 0.6.1 copy and metadata
corrections together with the first revision of the pairing-management
experience. Wire Protocol v2, the audio path, and the validation boundary are
unchanged.

## Pairing management

- **Server GUI:** a revoked device row offers **Re-pair** (open a fresh
  invitation) and **Delete** (remove the record permanently). Revoking still
  closes an active session within five seconds. Re-pairing an identity whose
  record is revoked shows an explicit **Restore device** confirmation; a plain
  accept never silently reactivates a revoked device.
- **Server GUI:** a consumed or expired QR code offers **Refresh QR code** first
  and keeps **Use pairing code** reachable without refreshing. A successful
  approval shows "`<name>` is paired."
- **Android Client:** the last authorization failure is persisted, so a revoked
  or reset Server shows **Needs re-pairing** even after a restart and no longer
  auto-connects. **Re-pair** keeps the cause and the address and explains that
  the Server operator must start pairing first. **Forget this Server** removes
  the saved pairing and its key after confirmation.
- Re-pairing the same phone keeps its identity across QR and SAS, so the Server
  updates one device record instead of creating a second one.
- **`as-cmd`:** `as-cmd clients delete <client-id>` removes a revoked record;
  active devices must be revoked first.

The 0.6.1 corrections are included: the v2 Android About page no longer labels
the app as a beta, the GUI and v2 About pages credit **© 2022-2026 Audio Share
contributors** under Apache-2.0, and the GUI home/update URLs,
`as-cmd --version`, and the Linux package homepage point at
`https://github.com/W0n9/audio-share`.

0.6.1 was tagged and built but not published as a GitHub Release; 0.6.2
supersedes it. Installs built from 0.6.0 or 0.6.1 can be overwritten in place
because the Android signing key is unchanged.

## Downloads

Each asset has a `.sha256` sidecar in `sha256sum` format. Verify a download
before opening it:

```sh
sha256sum -c audio-share-client-v2-0.6.2-arm64-v8a.apk.sha256
```

| Platform | Asset |
|---|---|
| Android (arm64 phones) | `audio-share-client-v2-0.6.2-arm64-v8a.apk` |
| Android (x86_64) | `audio-share-client-v2-0.6.2-x86_64.apk` |
| Windows GUI | `AudioShareServer.exe` |
| Windows headless | `audio-share-server-cmd-windows.zip` |
| Linux GUI (deb) | `AudioShareServer_0.6.2_amd64.deb` |
| Linux GUI (AppImage) | `AudioShareServer_0.6.2_amd64.AppImage` |
| Linux headless | `audio-share-server-cmd-linux.tar.gz` |

The v2 Server listens on UDP port 65531 (QUIC); allow it through the firewall.
Windows GUI requires the WebView2 Runtime; Linux GUI requires WebKitGTK 4.1,
GTK 3, the StatusNotifier appindicator, and a running PipeWire session with a
session manager. See the [README](../../README.md) for pairing, `as-cmd` flags,
and build instructions.

## Compatibility and upgrade

- One v2 Client per Server is supported; concurrent phones and multi-client
  isolation are outside this release.
- The v2 APK (`dev.audioshare.v2`) installs alongside the existing v1 Android
  app. The v1 APK and its F-Droid listing are not replaced. **Use v1 only on a
  trusted network:** it is unencrypted and unauthenticated. A failed v2
  connection never automatically falls back to v1 or plaintext.
- If an older v2 beta leaves stale credentials (error 205), use **Forget this
  Server** in the app and pair again. Uninstalling the old v2 app remains the
  fallback and also removes its saved pairings.
- Verify downloads against their accompanying SHA-256 checksums.

## Validation limits

Automated verification of the 0.6.2 source passed: Rust host 357 tests, GUI 114
tests, Android JVM 332 tests, `cargo fmt`, `cargo clippy -D warnings`,
`svelte-check`, and the production Vite build. On the Android emulator a revoked
identity was refused with 204, the SAS re-pair/restore path restored the same
device record, and credential reload passed; these are `EMULATOR` results, not
real-device acceptance.

The complete manual UI checklist (QR pairing, QR re-pair, Forget) and the real
Android device run are `NOT RUN` for 0.6.2. The 0.6.0 real-device and Windows
results cover the 0.6.0 artifacts only and do not transfer; the 0.6.2 artifacts
still need an install, playback, and Server run before publication.

The acoustic latency baseline, the 60-minute single-client run, real-network
impairment testing, device clock-drift injection, and listening A/B remain
waived or not run; this release does not claim the p95/p99 audible-latency
targets. Multi-client operation and full migration/rollback acceptance are
outside this release.
